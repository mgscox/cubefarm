# Discovering CubeFarm release skills

3 November 2026 · Research for [Verify how CubeFarm agents discover deployed skills](https://github.com/mgscox/cubefarm/issues/164). Evidence comes from the CubeFarm source, runtime documentation and the identified versioned interfaces. Discovery and invocation on deployed hosts remain to be exercised.

## Where agents start

CubeFarm's terminal runtime runs Claude Code, Codex, and OpenCode. Developer and QA desks can run on the office or on a linked worker box. The CEO and researchers stay on their office and use Claude Code. The SDK runtime uses Claude locally, and the worker interface rejects SDK sessions. A desk's working directory is its task worktree. The CEO works in the office's CEO directory, and research runs in a floor worktree or the company research directory. A skill checked into CubeFarm's own project discovery directory would be available when a runtime discovers that project, while other floor repositories and office state directories need an explicit registration path. [Placement and runtime selection](https://github.com/mgscox/cubefarm/blob/6a8eb2f45a2f81cbae14d78e5b1b1ecdaa9dbf77/server/swarm.ts#L1062-L1072) · [CLI selection](https://github.com/mgscox/cubefarm/blob/6a8eb2f45a2f81cbae14d78e5b1b1ecdaa9dbf77/server/swarm.ts#L2414-L2428) · [Desk preparation](https://github.com/mgscox/cubefarm/blob/6a8eb2f45a2f81cbae14d78e5b1b1ecdaa9dbf77/server/swarm.ts#L2555-L2565) · [CEO and research working directories](https://github.com/mgscox/cubefarm/blob/6a8eb2f45a2f81cbae14d78e5b1b1ecdaa9dbf77/server/swarm.ts#L4151-L4174) · [Research working directory](https://github.com/mgscox/cubefarm/blob/6a8eb2f45a2f81cbae14d78e5b1b1ecdaa9dbf77/server/swarm.ts#L4567-L4588) · [Remote runtime boundary](https://github.com/mgscox/cubefarm/blob/6a8eb2f45a2f81cbae14d78e5b1b1ecdaa9dbf77/server/boxLink.ts#L455-L465)

Both terminal hosts call `writeCliSession` on the machine launching the process. This is the shared place to resolve the skill directory from that machine's CubeFarm release, then pass a native flag or environment setting while retaining the task working directory. The SDK needs its own launch option. Each linked box follows its office's release through the existing version sync. A checkout can carry tracked files, while the current npm `files` list includes `bin`, `dist`, and `dist-server`, so a new top-level skills directory would require packaging work. ## Registration and collisions

| Runtime | Candidate for CubeFarm launches | Collision behavior and limits |
| --- | --- | --- |
| Claude Code terminal | Supply `--plugin-dir` pointing at one local plugin root with `skills/<name>/SKILL.md`. The flag loads it for that session. A dedicated `--add-dir` root containing `.claude/skills` is also documented, and loads that directory's `.claude/agents` and `.claude/commands` too. | Plugin skills have the qualified name `/plugin:skill` and can coexist with a plain skill. Plain enterprise, personal and project names resolve in that order. An added directory's colliding name is qualified in current versions, with that behavior documented from Claude Code v2.1.309. [CLI flags](https://code.claude.com/docs/en/cli-reference) · [Discovery and precedence](https://code.claude.com/docs/en/skills#resolve-skills-that-share-a-name) |
| Claude Agent SDK | Add the local plugin to `query()` as `plugins: [{ type: 'local', path: absoluteRoot }]`, alongside the existing user, project and local setting sources. The pinned SDK's local types expose `plugins`. SDK initialization lists the loaded plugin and qualified skills. | Same plugin namespace as Claude Code. Test local SDK launches separately from terminal launches. [SDK plugin API](https://code.claude.com/docs/en/agent-sdk/plugins) · [CubeFarm SDK configuration](https://github.com/mgscox/cubefarm/blob/6a8eb2f45a2f81cbae14d78e5b1b1ecdaa9dbf77/server/agentRunner.ts#L347-L372) |
| OpenCode v2 | Add `skills: [absoluteRoot]` to the launch's existing `OPENCODE_CONFIG_CONTENT`. CubeFarm runs with `--standalone` so each process gets its own config. The project documents v2.0.32, whose skill loader consumes configured `skills` sources. | Explicit sources outrank the implicit built-in, user and project directories. The last registered source for a given ID wins. The skill tool returns the skill base directory and example sibling paths. Skill permissions can hide or deny a skill. `OPENCODE_CONFIG_DIR` is documented for custom configuration in v1. The explicit v2 `skills` field fits CubeFarm's existing launcher and has a documented ordering rule. [CubeFarm OpenCode config](https://github.com/mgscox/cubefarm/blob/6a8eb2f45a2f81cbae14d78e5b1b1ecdaa9dbf77/docs/configuration.md#L58-L71) · [Launch arguments](https://github.com/mgscox/cubefarm/blob/6a8eb2f45a2f81cbae14d78e5b1b1ecdaa9dbf77/server/clis.ts#L245-L264) · [v2.0.32 skill loader](https://github.com/anomalyco/opencode/blob/v2.0.32/packages/core/src/config/plugin/skill.ts#L75-L158) · [v2 skills](https://dev.opencode.ai/v2/docs/skills/) · [v1 config](https://docs.opencode.ai/docs/config/#custom-directory) |
| Codex terminal | Investigate a local marketplace rooted in the release, with process `-c` overrides for the marketplace and the `plugin@marketplace` enabled state. Official docs establish those config keys and the precedence of CLI overrides. Validate whether this combination makes the local plugin usable on a fresh launch, including cache, installation and rollback behavior. | Standard standalone discovery scans the active repository's `.agents/skills` and user, admin and system roots. Two standalone skills with the same name can both appear. `skills.config` filters discovered skills by path or name, and `--add-dir` is documented as workspace write access. App-server separately provides process-level `skills/extraRoots/set` and listing overrides. The 0.166.0 local schema exposes the process setter, but CubeFarm's existing standalone TUI launch has no integration with that API. [Build skills](https://learn.chatgpt.com/docs/build-skills#where-codex-loads-local-skills) · [Configuration keys](https://learn.chatgpt.com/docs/config-file/config-reference) · [Override precedence](https://learn.chatgpt.com/docs/config-file/config-basic) · [CLI reference](https://learn.chatgpt.com/docs/developer-commands?surface=cli) · [App Server](https://learn.chatgpt.com/docs/app-server#skills) |

Codex CLI 0.166.0 source also scans `$CODEX_HOME/skills` for compatibility and labels that directory deprecated. A separate Codex home would scope that copy to processes launched with the alternate home, but also changes where Codex looks for its user config and runtime state. Consider this a version-specific fallback with login, settings and resume implications. The CLI source routes `--add-dir` to `additional_writable_roots`. [Codex 0.166.0 skill roots](https://github.com/openai/codex/blob/rust-v0.166.0/codex-rs/ext/skills/src/host_roots.rs#L112-L168) · [Codex 0.166.0 CLI argument handling](https://github.com/openai/codex/blob/rust-v0.166.0/codex-rs/cli/src/main.rs#L2115-L2125) · [Codex config reference](https://learn.chatgpt.com/docs/config-file/config-reference)

Keep each skill's complete directory available to the runtime. The Agent Skills format allows references, scripts and assets beside `SKILL.md`, and its relative references are resolved from that file's directory. Claude supports `${CLAUDE_SKILL_DIR}` and OpenCode v2 gives the model the base directory. Use a portable relative reference and verify each runtime can read it from a desk whose current directory is elsewhere. Claude Code's policy-managed enterprise skill directory has a wider scope than the CubeFarm launch. Home-directory placement similarly widens discovery to manual CLI sessions, and desk-directory placement would make skills discoverable to manual sessions started in that desk. ## Isolated acceptance checks

1. Use a fixture skill with a unique command and a nested `references/version.txt` containing an unmistakable release marker. Verify the runtime lists the expected skill, invokes it by its explicit name, and reads the marker from the release directory while its working directory is a different repo. The skill should use a read operation so it can also run as the CEO, whose Claude launch disables shell commands.
2. Exercise a local Claude terminal desk, a Claude SDK desk, a Codex terminal desk, and an OpenCode v2 desk. Repeat terminal checks through the worker's prepare and launch path on a separate test host. Cover a CEO and a researcher on an office so both non-desk paths are represented. Record each binary version, runtime discovery result and actual reference read.
3. In an isolated user profile and project, add a user skill and a project skill with the same name as the fixture. Record which names are listed and which marker each explicit name reads. Compare a CubeFarm launch with a plain CLI launch under the same test account and working directory. Check that its existing settings, login, session resume and hooks still work.
4. Validate both a checkout and an unpacked npm release, including paths with spaces. Deploy a second fixture version with a changed marker and one removed skill. Verify fresh sessions after update, worker reconnect and rollback. Record behavior separately for a keeper-adopted session and a resumed process so a new launch cannot be mistaken for an existing session changing its inputs.

These checks leave the collision policy, release layout, version floor, and whether any fallback is acceptable to the remaining Wayfinder decisions.
